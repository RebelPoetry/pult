# План реализации Ф1 — демон `pultd` и CLI `pult` (решение лида, 21.09.2026)

Основание: `04-DELTA-v0.3.md` (модель поставки), `05-DELTA-v0.4-spike.md` (Codex, opencode, окружение), `06-DELTA-v0.5-spike-claude.md` (Claude, сеть). Всё, что здесь названо фактом, измерено спайком.
Вне Ф1: Electron-оболочка, адаптер opencode (Ф1.5), доска и движок флоу, Telegram, расписание, автоматический failover, git-сервис шире `--worktree`.

## 1. Решения реализации
- Язык: TypeScript, компиляция `tsc` в `dist/` (ESM, target ES2022, `strict`). Причина: типы событий и RPC в Ф2 импортирует интерфейс. Рантайм-зависимостей НОЛЬ; devDependencies — только `typescript` и `@types/node`.
  `package-lock.json` коммитится, CI делает `npm ci`. Тесты — встроенный `node:test` по скомпилированному коду. Требование к машине: Node ≥ 22.
- Один пакет `pult` (разбиение на пакеты — когда появится интерфейс). `bin`: `pult` → `dist/cli/main.js`, `pultd` → `dist/daemon/main.js`.
- Состояние: `PULT_HOME` (по умолчанию `~/.pult`). Все тесты работают только с `PULT_HOME` во временной папке. Раскладка: `run/{pultd.sock,token,pultd.lock}`, `events/<session>.jsonl`, `sessions.json`, `config.json`, `logs/pultd.log`.
- Код спайка переносится, а не переписывается с нуля: сокет+токен+lock (`spike/env/sock-server.mjs`), обновление с откатом (`spike/env/update.mjs`), лаунчер и шаблоны службы (`spike/env/service/*`),
  поиск CLI и захват окружения (`spike/env/locate-cli.mjs`, `capture-env.mjs`), запуск `claude`, ожидание результата, страж страны выхода, белый список окружения (`spike/claude/lib.mjs`), заглушка MCP (`spike/claude/mcp-ask-stub.mjs`),
  клиент app-server (`spike/codex/client.mjs`). Спайк остаётся в репо как доказательства и не импортируется продуктовым кодом.

## 2. Каталоги
```

src/perm/      broker (Inbox), mcpAsk (stdio MCP-заглушка, режим `pult mcp-ask`)

```

## 3. Протокол демона (версия 1)
- Транспорт: unix-сокет `PULT_HOME/run/pultd.sock`, каталог 0700, файлы 0600 явным `chmod`. JSON построчно. HTTP-порта нет.
- Рукопожатие: первое сообщение клиента `{"type":"hello","token":"…","client":"cli|shell|mcp-ask","protocol":1}` → `{"type":"hello_ok","protocol":1,"daemon":{"version","pid","startedAt"}}`.
  Неверный токен → `{"type":"error","code":"bad_token"}` и разрыв; молчание 2 с → `handshake_timeout`; не-hello первым → `handshake_required`; мусор → `bad_json`. Токен меняется на КАЖДОМ старте демона.
- Запрос/ответ: `{"id","method","params"}` → `{"id","result"}` | `{"id","error":{"code","message","data?"}}`. Коды ошибок — строки (`not_found`, `invalid_params`, `provider_unavailable`, `blocked_network`, `timeout`, …).
- Подписка: `events.subscribe {since?: number, sessionId?: string}` → сначала доигрываются события с курсора, потом живые; кадры `{"sub": <id>, "event": {…}}`. Курсор = монотонный номер события демона, переживает рестарт (хранится в журнале).
- Конверт события: `{"id": number, "ts": ISO, "sessionId", "parentId"?, "provider": "claude|codex|pult", "kind", "data"}`. Виды — словарь страницы: `session.started|ended`, `message.delta|done`, `tool.called|finished`,
  `agent.spawned|finished`, `permission.requested|resolved`, `question.asked`, `usage.updated`, `limit.hit`, `net.blocked`, `provider.blocked`, `provider.restarted`, `status.changed`, `daemon.started|stopping`.
  `provider.restarted` добавлен в В3: общий процесс провайдера умер или поднят заново (pid, код, сигнал, поколение, число перезапусков в окне). Пишется в сессию `daemon`, потому что он про провайдера, а не про чью-то работу.
- Методы Ф1: `daemon.status`, `daemon.stop`, `doctor.run`, `agent.start`, `agent.prompt`, `agent.read`, `agent.wait`, `agent.list`, `agent.stop`, `agent.rm`, `agent.tree`, `perm.list`, `perm.resolve`, `events.subscribe`, `events.tail`, `usage.get`.
- Один экземпляр: lock `open(O_CREAT|O_EXCL)` с pid, живость `kill(pid,0)` (`EPERM` = жив), старый сокет удаляется ТОЛЬКО после взятия lock. Второй демон выходит с кодом 3.

## 4. CLI `pult` (глаголы herdr, структурный вывод)
`pult daemon start|status|stop|logs|install|uninstall` · `pult doctor [--json]` · `pult agent start <name> --kind claude|codex --cwd <dir> [--worktree <имя>] [--model M] [--effort E] [--warm]` ·
`pult agent prompt <name> "текст" [--wait] [--until idle,blocked,done] [--timeout MS] [--json]` · `pult agent read <name> [--since <id>] [--format text|json]` · `pult agent wait|list|stop|rm|tree` ·
`pult perm list|approve <id>|deny <id> --reason "…"` · `pult events tail [--since <id>]` · `pult update [--to <версия>]` · `pult mcp-ask` (служебный режим заглушки).
Коды выхода: 0 ок · 1 ошибка · 2 таймаут · 3 ждёт человека · 4 сеть заблокирована стражем · 5 провайдер недоступен (сюда же исчерпанный лимит подписки — `errorCode: limited`). Имена агентов `[a-z][a-z0-9_-]{0,31}`. Промпт идёт в stdin дочернего процесса, не в argv.
Демон поднимается по требованию: любая команда, которой он нужен, запускает его отсоединённым, если сокет не отвечает.

## 5. Инварианты (каждый закреплён тестом)
1. Окружение дочернего процесса строится по БЕЛОМУ списку (HOME, USER, PATH, LANG, TERM, TMPDIR + профиль сети). Ни одна `ANTHROPIC_*` / `CLAUDE_*` / `OPENAI_*` переменная родителя не попадает ребёнку.
2. Страж страны выхода: перед первым ходом сессии и перед ходом после простоя > 60 с — запрос `…/cdn-cgi/trace` тем же путём, что пойдёт ребёнок. Страна в списке-страже или неизвестна → ход не запускается, событие `net.blocked`, код выхода 4.
   Проба прокси — настоящий запрос, не TCP-коннект. Режимы `auto | required | off` на провайдера, страж действует во всех.
3. Текст `/disabled Claude subscription access/` → `provider.blocked`, провайдер остановлен целиком, повторов нет. Три подряд `system/api_retry` → ход прерывается.
4. Результат хода Claude судится по `is_error` и `terminal_reason`, не по `subtype`. «Ход завершён» ≠ «работа завершена»: при `subagent_stats.started_in_background > 0` статус сессии `working`, а не `idle`.
5. Заглушка разрешений при недоступном демоне отвечает ОТКАЗОМ. Нода без хозяина разрешений запускается с `--permission-prompts none`.
   ПЕРЕСМОТР M8d (решение владельца 19.10.2026): «да» по умолчанию — по-прежнему один раз, но стоячие разрешения теперь бывают — ТОЛЬКО по явной кнопке человека («В этой сессии» → `acceptForSession`, «Всегда …» → поправка execpolicy или правило сети Codex) и только когда провайдер предложил их на этот запрос; ⌘Enter и голое `perm approve` шире одного раза не бывают. Отказ, таймаут, остановка — как раньше (docs/DEV.md, раздел M8d).
   `perm.request` доступен только клиенту `mcp-ask` И только под именем сессии, заведённой в реестре: имени-призрака в Inbox быть не может.
   `updatedInput` при `allow` НЕ проверяется на вложенность в `cwd` сессии, и это решение, а не недосмотр: поле существует ровно затем, чтобы человек мог перенаправить правку, и человек здесь — высшая инстанция.
   Агент своими силами расширить разрешение не может: `updatedInput` приходит от того, кто жмёт `perm approve`, а не из потока модели. Захотим границу по `cwd` — она встанет в `perm.resolve` и будет отдельным инвариантом.
6. Codex: каждое уведомление разбирается по `threadId`; текст хода собирается из `item/completed`; запросы разрешений отвечаются по id JSON-RPC-запроса, варианты — из `availableDecisions` там, где схема параметров это поле объявляет (это только `item/commandExecution/requestApproval`), иначе из словаря решений самого метода; resume с `excludeTurns: true`.
7. Пульт не читает `~/.claude/.credentials.json`, keychain, `~/.codex/auth.json`; в журнал не пишутся адреса почты и токены (фильтр на запись + тест).
8. Никаких записей вне разрешённых мест. Запись разрешена: в `PULT_HOME`; в рабочую папку сессии и её worktree; в `.git` исходного репозитория
   (служебные файлы `git worktree`); в файл службы (`~/Library/LaunchAgents/<label>.plist` или `~/.config/systemd/user/<unit>`) — ТОЛЬКО по явной
   команде `pult daemon install|uninstall`; в `<bin-dir>/pult` — только `install.sh`. Всё остальное — нарушение, закреплённое тестом
   (уточнение формулировки — `08-PLAN-F1-M4.md` §8).

## 7. Порядок работы
Каждая веха — воркфлоу: сборка (opus) → атака (тестировщик-взломщик, ревьюер кода, Codex как вторая модель) → правки → PR с зелёным CI. Лид сам читает ключевые файлы, гоняет тесты и пробует CLI руками, потом мёржит.
Настоящие CLI в тестах CI не используются. Дымовые прогоны тратят крошечные ходы и идут только со стражем выхода.
