## 3. opencode: три ошибки v0.3 и остальное
- ОШИБКА 1 · порт. `opencode serve --port 0` НЕ даёт случайный порт: сервер садится на стандартный 4096 и берёт другой только при коллизии. Демон сам выбирает свободный порт и передаёт его явно (`--port <n>`).
- ОШИБКА 2 · разрешения. В 1.18.31 ДВА ДВИЖКА, а не старые и новые имена одного. `POST /session/{id}/prompt_async` (и синхронный `/session/{id}/message`) → события `message.part.*`, `session.status`, `session.idle`,
  `permission.asked`. `POST /api/session/{id}/prompt` → отдельный движок со своим хранилищем сообщений: `session.next.*`, `permission.v2.*`, конец хода — `session.next.step.ended`. Пульт использует ПЕРВЫЙ движок.
  Поэтому: событие — `permission.asked`; ответ — `POST /permission/{requestID}/reply?directory=…` с телом `{"reply": "once" | "always" | "reject"}` (значения «allow» нет).
  Путь `/api/session/{id}/permission/{requestID}/reply` с этим движком отвечает 404 `PermissionNotFoundError`. Таблицу соответствия имён между движками НЕ писать.
- ОШИБКА 3 · лимит. `session.status: retry` — это НЕ сигнал лимита: мёртвый прокси дал пять таких статусов подряд. Отличие — необязательный блок `action` {reason, provider}: `retry` БЕЗ `action` = нет сети.
  Цикл `retry` сам не заканчивается: адаптеру нужен свой потолок (попытки или время) и `abort`. Статус Пульта `limited` — только при `retry` с `action`.
- Пароль ПОДТВЕРЖДЁН и ОБЯЗАТЕЛЕН: с `OPENCODE_SERVER_PASSWORD` все пути, включая `/doc` и SSE `/event`, отдают 401 без авторизации. Схема — HTTP Basic, пользователь по умолчанию `opencode`.
  Без пароля защиты нет вообще: чужой `Origin` и чужой `Host` получают 200, страница в браузере может СОЗДАТЬ сессию. Демон отказывается запускать `opencode serve` без пароля; `--cors` и `--mdns` не передаёт никогда.
- Папка: одного `?directory=` достаточно, два сеанса в разных папках на одном сервере независимы, потоки `/event?directory=` не пересекаются. `directory` — НЕ граница доступа: сессия по id доступна с любым значением.
- Субагенты: в родителе это часть `tool` с `tool: "task"` (а не часть `subtask`), дочерняя сессия с `parentID`. События ребёнка идут в тот же поток. ЛОВУШКА: ребёнок тоже шлёт `session.idle` —
  конец хода определять по `sessionID` родителя, иначе первый же субагент «завершит» родительский ход.
- Схема ответа: результат в `AssistantMessage.structured` (событие `message.updated`). Реализована принудительным вызовом инструмента, поэтому ЗАВИСИТ ОТ МОДЕЛИ: `nemotron-3.5-lightning-free` вернула схему,
  `muse-spark-1.3-contributor-free` упала у провайдера («only "auto" is supported for tool_choice»). В живом списке флага возможностей нет → у класса «дешёвый исполнитель» появляется ПРОБНАЯ таблица возможностей
  на модель; нода-гейт со схемой не получает произвольную бесплатную модель; ошибка `tool_choice` показывается как «эта модель не умеет ответ по схеме».
  Формулировка «контракт стрелки принудителен у всех трёх» уточняется: у opencode — для моделей, прошедших пробу.
- Остановка: `POST /session/{id}/abort`. Перед `idle` приходит `session.error` с `MessageAbortedError` — это НЕ красная ошибка, а запрошенная остановка; частичный текст не сохраняется. Лог остановки посреди хода слабый → перепроверить в Ф1.5.
- Resume, расход, список моделей — как в v0.3: сессии в базе opencode, `info.tokens` и `info.cost` на сообщение, 7 бесплатных моделей сейчас (`cost.input == 0 && cost.output == 0`), ключ Zen на месте.
- Плохой прокси у opencode не падает быстро, а уходит в бесконечный `retry` → проба прокси в `pult doctor` — отдельный исходящий запрос, а не «запустим ход и посмотрим».

## 4. Окружение и служба
- Окружение дочерних процессов строится по БЕЛОМУ СПИСКУ (HOME, USER, PATH, LANG, TERM, TMPDIR + профиль сети), а не вычищением плохого. Процесс, запущенный из десктопного приложения Claude, несёт 25 переменных
  `ANTHROPIC_*` / `CLAUDE_*`, включая `ANTHROPIC_BASE_URL` и `CLAUDE_CODE_MESSAGING_SOCKET`: первая молча перенаправит API, вторая подключит ребёнка к чужой сессии. Захват логин-шелла выполнять под `env -i`.
- В логин-шелле владельца НЕТ прокси-переменных вообще (прокси живёт только в zsh-функции, `env -0` её не видит). Единственный источник профиля сети — `~/.pult/config.json`; `pult doctor` не пишет «прокси найден в шелле».
- Поиск CLI обязателен: 6 из 7 CLI не видны в PATH службы launchd. В список кандидатов добавить `/opt/homebrew/bin/claude` раньше `~/.claude/local/claude`. Из PATH выбрасывать нераскрытые `~` и дубли.
- plist ОБЯЗАН нести `EnvironmentVariables.PATH` (иначе `pultd-launch` не найдёт даже `node`) и `ThrottleInterval`. В unit `StartLimitIntervalSec` и `StartLimitBurst` — в секции `[Unit]`. Unit без Linux не проверить → задача CI до Ф7.
- `pultd-launch` первой строкой задаёт себе PATH (`/usr/bin:/bin:/usr/sbin:/sbin`): первая версия умерла с `date: command not found`. Ошибка конфигурации выходит с кодом 78, чтобы `pult doctor` отличал
  «служба указывает на несуществующий node» от «демон упал».
- Установка: нужна `npm install --global --prefix ~/.pult/versions/<v> <tarball>`. Без `--global` npm делает `node_modules/.bin`, а не `bin/`, и симлинк `~/.local/bin/pult` повис бы. Установка локального тарбола полностью офлайн (249 мс,
  сеть нужна только чтобы скачать тарбол). Переключение `current` — атомарным `rename`. Автооткат после трёх неудачных стартов доказан, файлы работающей версии не трогаются.
- Сокет: каталог 0700 и файлы 0600 — явным `chmod` (umask маскирует режим `mkdir`); lock — `open(O_CREAT|O_EXCL)`, живость через `kill(pid, 0)`, `EPERM` = жив; старый сокет удалять ТОЛЬКО после взятия lock;
  токен менять на каждом старте; молчащий клиент отбрасывается через 2 с.
- Доступ к `~/Desktop` не проверялся (нужна загруженная служба и клик человека): шаги в `spike/env/HUMAN-STEPS.md`. Новый риск: разрешение macOS привязывается к `/opt/homebrew/bin/node` — общему бинарю;
  `brew upgrade node` может его сбросить. Это довод в пользу самодостаточного бинаря демона, если диалог начнёт возвращаться.

## 5. Claude: что известно без входа
- Результат хода судить по `is_error` и `terminal_reason`, НИКОГДА по `result.subtype`: при ошибке входа приходит `{"subtype": "success", "is_error": true, "terminal_reason": "api_error"}`.
- Событие `system/init` приходит ДО авторизации и без квоты: полный список инструментов, агентов, скиллов, слэш-команд, MCP. Это бесплатная проба для `pult doctor` и для реестра.
- `--setting-sources user` ПРЯЧЕТ проектные воркфлоу и скиллы (50 команд против 51). Дешёвый старт и проектные воркфлоу взаимоисключающи → `setting-sources` — переключатель НОДЫ: мини-сессия — `user`,
  запуск воркфлоу — `user,project`.
- `claude auth status --json` при `loggedIn: false` выходит с кодом 1, печатая корректный JSON: читать stdout, код выхода игнорировать. `<подкоманда> --help` без входа печатает «Not logged in» вместо справки.
