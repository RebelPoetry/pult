# Идеи Kent, Orca и Pi в Пульте — решение лида (06.10.2026)

Источники (смотрены 02–05.10.2026):
- [Kent](https://kent.sh/workflows/) — свой агент + Kent Desktop: воркфлоу графом, канбан задач. AGPL-3.0, только
  OpenAI-совместимые API и локальные модели; **Claude и Gemini не поддерживает** (ссылается на условия провайдеров).
- [Orca](https://www.onorca.dev/) — «среда агентской разработки»: окно над 27+ CLI (Claude Code, Codex, OpenCode…),
  worktree на агента, лента агентов, комментарии к диффу, мобильный компаньон. MIT.
- [Pi](https://pi.dev/) — минимальный агент-харнесс: дерево сессий с ветвлением, подруливание хода, расширения. MIT.

Это разбор идей, не адаптер и не зависимость. **Код Kent не копируем** (AGPL) — только модель и термины.

**Клин Пульта после разбора:** воркфлоу как у Kent, но на подписках Claude и Codex и бесплатных моделях opencode,
три провайдера в одном графе; живой прогон на холсте с деревом субагентов внутри ноды; линтер флоу по нашим тирам.
У Kent нет Claude, у Orca нет графа воркфлоу, у Pi нет ни окна, ни оркестрации.

## Решения владельца (05.10)

1. Граф доски — **модель Kent: переходы и циклы.** Заменяет «граф без циклов, нода стартует, когда закрыты все
   входящие стрелки» из раздела 09 страницы v0.6.
2. Канбан задач — **в Ф4 вместе с ветками** (задача = worktree + ветка + PR). В Ф3 — только холст и прогоны.

## Модель флоу v2 (Ф3)

Файл — `.pult/flows/<имя>.flow.json`, рядом `flow.schema.json` (нужна редактору, линтеру и агенту, который пишет флоу).
Нода — **кто** работает, переход — **что** ему сказать и **что** вернуть.

```json
{
  "version": 2,
  "name": "feature-review-loop",
  "nodes": {
    "start":     { "kind": "start" },
    "implement": { "kind": "agent", "provider": "claude", "model": "sonnet", "effort": "medium", "maxVisits": 4 },
    "tests":     { "kind": "script", "run": "./scripts/ci-check.sh", "mode": "exit", "timeoutSec": 900 },
    "reviews":   { "kind": "group", "children": ["review_claude", "review_codex"], "join": "collect" },
    "review_claude": { "kind": "agent", "provider": "claude", "model": "opus", "effort": "high", "judges": "implement" },
    "review_codex":  { "kind": "agent", "provider": "codex", "effort": "low" },
    "collect":   { "kind": "join" },
    "triage":    { "kind": "agent", "provider": "claude", "model": "opus", "effort": "high", "judges": "implement" },
    "done":      { "kind": "terminal" }
  },
  "transitions": [
    { "from": "start", "key": "begin", "to": "implement", "prompt": "Задача: {{task.title}}\n{{task.body}}" },
    { "from": "implement", "key": "ready", "label": "Готово к проверке",
      "describe": "код написан, локально собирается", "to": "tests",
      "params": { "summary": "что сделано, 3–5 буллетов" } },
    { "from": "tests", "key": "fail", "to": "implement", "context": { "mode": "continue" },
      "prompt": "Тесты упали:\n{{params.log}}" },
    { "from": "tests", "key": "pass", "to": ["review_claude", "review_codex"],
      "prompt": "Проверь изменения. Автор пишет: {{params.ready.summary}}" },
    { "from": "review_claude", "key": "reviewed", "to": "collect", "params": { "findings": "находки с путями" } },
    { "from": "review_codex",  "key": "reviewed", "to": "collect", "params": { "findings": "находки с путями" } },
    { "from": "collect", "key": "joined", "to": "triage",
      "prompt": "Claude: {{params.review_claude.findings}}\nCodex: {{params.review_codex.findings}}" },
    { "from": "triage", "key": "needs_changes", "to": "implement", "approval": true,
      "context": { "mode": "continue" }, "params": { "fixes": "что править" },
      "prompt": "Ревью вернуло правки:\n{{params.fixes}}" },
    { "from": "triage", "key": "approve", "to": "done", "approval": true }
  ]
}
```

### Движок
- **Ответ агентной ноды** — объединение схем её исходящих переходов: `{transition: <ключ>, commentary, …params этого
  перехода}`. Принуждение схемы у всех трёх уже доказано спайком Ф0. Ответ не по схеме → одна повторная реплика с текстом
  ошибки валидатора → нода `failed` → карточка в Inbox.
- **Циклы.** `maxVisits` на ноде (по умолчанию 3). Превышение → задача встаёт, в Inbox «цикл упёрся»: +1 заход / выбрать
  переход руками / остановить. У Kent от вечного цикла страхует только обязательный `ask_question`; у нас агент и так
  может спросить через Inbox (`src/perm/mcpAsk.ts`), но потолок нужен всё равно — он дешевле подписки.
- **Веер.** Переход с массивом `to` стартует ветки параллельно; ветки группы обязаны прийти в её `join`. Join ждёт все,
  у него ровно один исходящий переход, параметры веток доступны как `params.<нода>.<поле>`. Решение после веера
  принимает следующая нода (агент или скрипт), не join. Упавшая ветка → Inbox: повторить / пропустить (поля пустые) /
  остановить.
- **Кэш ног** — ключ `(задача, нода, номер захода, хэш входа)`. После перезапуска демона нода, не дошедшая до ответа,
  исполняется заново с теми же параметрами (у Kent так же).
- **Шаблоны** — `{{task.*}}`, `{{params.<поле>}}` (из входящего перехода), `{{params.<ключ перехода или нода>.<поле>}}`
  (из более ранних). Без логики: ни условий, ни циклов в шаблоне.

### Режим контекста на переходе в агентную ноду
| Режим | Что | Claude | Codex | opencode |
|---|---|---|---|---|
| `new` (по умолчанию) | свежая сессия: ревью, QA | новая сессия | `thread/start` | новая сессия |
| `continue` | та же история и кэш: «тесты упали — почини» | `--resume <id>` | `turn/start` в том же треде | реплика в ту же сессию |
| `compact` | сжать и продолжить: большой переход между фазами | не проверено в `-p` | `thread/compact/start` (в схеме) | `POST /session/{id}/summarize` (в OpenAPI) |

- `context.of` — чью сессию продолжать: по умолчанию `from`; `"self"` — прошлую сессию самой целевой ноды, а на первом
  заходе новую. Это закрывает петлю повторного ревью: ревьюер видит, что он просил в прошлый раз. Четыре варианта Kent
  сводятся к этим двум.
- `continue` и `compact` — только при одном провайдере на обоих концах; редактор не даст сохранить иначе.
- `compact` скрыт в редакторе, пока проверка 1 ниже не пройдена у провайдера.

### Гейт на переходе
Агент выбрал переход с `approval: true` → задача ждёт, в Inbox карточка: подпись перехода, `commentary`, параметры,
дифф ноды (в Ф3 — `git diff` рабочей папки от старта ноды, в Ф4 — с комментариями к строкам). Действия: одобрить /
отклонить с текстом (возврат в ноду-источник в режиме `continue` с репликой «человек отклонил переход X: …», нода
выбирает заново) / выбрать другой переход. В Ф6 то же из Telegram.

### Скрипт-нода
- `mode: "json"` (контракт Kent): stdin — параметры + `_pult: {task, node, visit, branch}`; stdout — последняя строка
  JSON `{transition, commentary, …params}`. Один исходящий переход — `transition` можно не писать.
- `mode: "exit"` (наше, для тестов и линтеров, которые JSON не печатают): код 0 → переход `pass`, иначе `fail`, хвост
  stdout+stderr (последние 200 строк) — в `params.log`.
- Ненулевой код в `json`, невалидный JSON, таймаут → нода прервана → Inbox (повторить / остановить); повтор — с теми же
  параметрами. Окружение — через наш белый список (`src/env/allowlist.ts`), рабочая папка — корень задачи.
- Первые кандидаты: `./scripts/ci-check.sh`, `python3 scripts/check_model_tiers.py`, `forge probe`, `bzf probe`.

### Редактор и прогон (React + xyflow, как в v0.6)
- Холст: ноды пяти видов (start, agent, script, group+join, terminal), стрелки с подписью перехода; гейт — замок на
  стрелке, `continue` — сплошная, `new` — пунктир.
- Инспектор ноды: провайдер, модель (opencode — из живого списка, класс `cost == 0`), усилие, агент `.md` или скилл,
  `maxVisits`, `judges`. Инспектор перехода: ключ, подпись, описание для модели, параметры, промпт с автодополнением
  доступных плейсхолдеров, режим контекста, гейт.
- Прогон на том же холсте: цвет ноды по статусу сессии (`working`, `blocked_*`, `failed`, `idle`), бейдж захода «2/4»,
  пройденные стрелки подсвечены. Клик по ноде — **рентген**: разговор её сессии, дерево субагентов (то же, что
  `pult agent tree`), расход. Внизу лента переходов с параметрами — история прогона.
- **Перезапуск с ноды** (Pi): на завершённой или упавшей ноде — «перезапустить отсюда» с правкой промпта перехода;
  ноги до неё берутся из кэша, старая ветка прогона остаётся видна. Форк самой сессии (`--fork-session`, `thread/fork`,
  `POST /session/{id}/fork`) — позже, сначала хватит свежей сессии на тех же параметрах.

### Линтер флоу (при сохранении и перед запуском)
- **Судья не слабее автора:** у ноды с `judges: <нода>` модель не ниже модели автора по порядку тиров из
  `.claude/model-tiers.json` воркспейса (haiku < sonnet < opus < fable). Судья другого провайдера — «второе мнение»,
  тир не сравнивается: шкалы Claude, Codex и opencode несопоставимы.
- Каждый плейсхолдер в промпте гарантирован на **всех** путях в ноду (поток данных по графу, циклы учитываются).
- Каждый цикл проходит хотя бы через одну ноду с `maxVisits`; каждая агентная нода имеет исходящий переход; terminal
  достижим; каждая ветка группы приходит в её join.
- Оценка цены прогона до запуска («≈ N% окна Claude, M ходов Codex, opencode бесплатно») — Ф6, когда будут лимиты.

## Ф4: канбан, worktree, дифф

- **Канбан.** Задача = `{title, body, flow, labels, blockedBy}` — долгоживущая единица, которая идёт по флоу. Колонки =
  ноды флоу (start = «Бэклог», terminal = «Готово»), на карточке — нода, заход и значок «ждёт тебя». Задача с
  `blockedBy` стартует, когда блокирующие дошли до terminal.
- **Политика worktree на флоу** (Kent): `ask` (спросить при старте) / `head` (от текущего коммита) / `default` (от
  ветки по умолчанию) / ревизия. Имя ветки — короткий id задачи. Сводится вместе со стратегиями слияния и правилом
  reuse из `12-PLAN-sandcastle-ideas.md`.
- **Комментарии к строкам диффа** (Orca): на карточке гейта и в любой момент — комментарий к строке уходит агенту
  репликой (`continue`) или полем отказа на гейте. Так петля Kent «ревью → правки» замыкается через человека.
- Срок Ф4: 2 → 3 недели.

## Мелкое

- **Подруливание хода** (Pi) — реплика агенту посреди хода, в чате окна. Codex — `turn/steer` (в схеме app-server);
  Claude и opencode — проверка 2. Ф2 О2, если проверка прошла; иначе — только «прервать и сказать».
- **Лента агентов** (Orca) — в ленту О2 добавить превью ответа и событие «задача упёрлась / ждёт тебя».
- **Флоу из моих скиллов и логов** (Kent) — мини-сессия Ф5 на `.flow.json`: агент читает `.claude/agents`, скиллы,
  `.claude/workflows/*.js` и журнал прошлых сессий, пишет флоу по `flow.schema.json`, линтер проверяет.
- **Запасной провайдер ноды** — `fallback: {provider, model}` на ноде, срабатывает на `limited`; «прошлая нода выбирает
  модель следующей» (Kent) — там же, Ф6, только из ролей, явно помеченных как выбираемые.

## Проверки перед Ф3 (2–3 вечера, в стиле спайка Ф0)

1. `compact`: Claude — работает ли `/compact` репликой в `claude -p --input-format stream-json` и что приходит в поток;
   Codex — `thread/compact/start` и уведомление `thread/compacted`; opencode — `summarize` и часть `compaction`.
2. Подруливание: Claude — реплика в stream-json посреди хода (встаёт в очередь или вклинивается?); opencode —
   `prompt_async` в занятую сессию; Codex — `turn/steer` на живом ходе.
3. `continue` со сменой модели: Claude `--resume` + другой `--model`; Codex — модель на `turn/start` в том же треде.
4. Ответ-объединение схем (`oneOf` по `transition`) — принимают ли его все три принуждения схемы; нет → плоская схема
   с `transition: enum` и всеми полями необязательными + проверка на нашей стороне.

## Что меняется в плане

- **Ф3: 4 → 5 недель, жёсткий потолок.** Формат v2 + схема, движок переходов (циклы, группы, join, гейт на переходе,
  кэш по заходам), режимы `new`/`continue`, скрипт-нода, редактор, прогон на холсте с рентгеном, линтер, перезапуск с
  ноды, два шаблона («фича с ревью-циклом», «план → реализация → тесты»). Порядок резки при упоре в потолок:
  перезапуск с ноды → Ф5; `context.of: "self"` → Ф5; автодополнение плейсхолдеров → Ф5.
- **Приёмка Ф3 (новая):** флоу «фича с ревью-циклом» собран мышью; ревью хотя бы раз вернуло `needs_changes`, и цикл
  закрылся; скрипт-нода `ci-check.sh` хотя бы раз отправила в `fail → implement`; один переход прошёл через гейт в
  Inbox; одна нода исполнена Codex, одна — бесплатной моделью opencode; прогон пережил перезапуск демона.
- **Ф4: 2 → 3 недели** (канбан, политика worktree, комментарии к диффу).
- Итого ~19 → ~21 неделя вечеров. Страница v0.6 (раздел 09 и роадмап) переписывается в v0.7 на старте Ф3, после
  проверок выше.

## Не берём

- **Kent:** свой агент и инструменты (`patch`/`shell`/`ask`) — Пульт надстройка над CLI; роли в TOML — у нас
  `.claude/agents/*.md`; режимы завершения (structured / tool call / shell / unstructured) — схема принудительна у всех
  трёх; супервизор-агент; код под AGPL.
- **Orca:** GPU-терминал, встроенный VS Code, браузер с design mode (для игр вместо него — кадры game-forge/bzf как
  вложение карточки гейта, когда понадобится), SSH-worktree, мобильные приложения (их место занимает Telegram в Ф6),
  переключатель аккаунтов, Windows.
- **Pi:** система расширений и пакетов, темы, свой харнесс, вход по API-ключам — Пульт ключей не трогает.
