## Зачем

- Одна задача в одном чате несколькими моделями: Claude и Codex тегают друг друга, как в Telegram. Потом qwen-code
  и другие CLI.
- Самый проверенный выигрыш — роли **«автор + ревьюер другой модели»**. Свободный чат — второй режим.
- **Главный риск не в коде, а в пользе:** модели легко соглашаются друг с другом. Поэтому К0 — сначала проверка пользы.

## К1 — комната в демоне, 2–3 дня

- **Сущность `room`:** имя, проект/cwd, участники (имена существующих сессий Пульта), у кого «руки», лимит передач,
  режим (автор+ревьюер | свободный).
- **События журнала:**
  - `room.created`;
  - `room.message {author: human|<сессия>, text, mentions[]}`;
  - `room.routed {to, turnId}`;
  - `room.hop_limit`;
  - `room.writer.changed`.
- **Маршрутизация:**
  - реплика человека с `@имя` → этим участникам;
  - без тега → ведущему (участник по умолчанию или последний адресат);
  - ответ агента — его `TurnOutcome.text` (адаптер: `send(name, text)` → `TurnStarted{turnId, done}`) → в комнату;
  - теги в ответе → следующий ход адресата; без тегов → ход возвращается человеку.
- **Разбор тегов:**
  - только по известным участникам, на границе слова;
  - **не** внутри блоков кода и цитат — иначе агент, процитировавший «@codex», запустит ход.
- **Доставка.** Перед ходом агент получает:
  - шапку: комната, участники, кто держит руки, правила («тегай, только если нужен ответ; благодарность — без тега»);
  - дельту комнаты с его прошлого хода, с подписями авторов.
  - Только итоговые тексты ходов, без выводов инструментов — иначе раздувается контекст.
- **«Одни руки».** Писать в файлы может один участник, остальные читают и ревьюят.
  - Не-писатель: Claude — запрет записи на ход, Codex — read-only песочница (по итогам К0).
  - Запасной путь: брокер отказывает в Edit/Write не-писателю с текстом «руки у @…, попроси тегом».
  - Передача рук — тегом-командой или кнопкой.
  - Один cwd на комнату (руки одни — конфликтов нет); worktree на участника — в «гонке» Ф4.
- **Лимит передач:** по умолчанию 6 на одну реплику человека, потом `room.hop_limit` и комната ждёт человека.
  «Стоп всем» прерывает всех участников.
- **Занятый адресат** → очередь реплик демона (M4).

## К3 — адаптер ACP (0.5), 3–5 дней + 1–2 дня на каждый новый CLI

- Один адаптер к Agent Client Protocol (Zed) вместо адаптера на каждый CLI:
  - `initialize`, `session/new`, `session/prompt`;
  - поток `session/update`;
  - `session/request_permission` → брокер / Inbox;
  - `session/cancel`.
- Правило распознавания провала из спайка Hermes (K2, [`09-DELTA-hermes-spike.md`](09-DELTA-hermes-spike.md)) переносится:
  по одному `usage` провал не распознать, нужен текст реплики.
- **Первая цель — qwen-code.** Кандидаты: Gemini CLI, goose, Kimi CLI (поддержку ACP сверить при старте).
- Ключи и вход — в конфиге самого CLI, Пульт ключей не читает (как сейчас).
- DeepSeek — моделью через qwen-code или opencode по API-ключу (оплата за токены).
- Claude и Codex остаются на родных адаптерах.
- Это **пересматривает** пункт «ACP-адаптер» из «Не берём» плана 14.

## Голосовой ввод — позже (~2–3 вечера)

- Уже сейчас бесплатно работает системная диктовка macOS в поле ввода окна. Whisper нужен ради смеси русского
  и английских терминов и офлайна.
- Кнопка микрофона / удержание горячей клавиши → запись в окне (MediaRecorder) → WAV 16 кГц → RPC демона →
  локальный whisper.cpp (или MLX-вариант — выбрать при старте).
- Модель large-v3-turbo скачивается по требованию в `PULT_HOME/models` с проверкой sha256, как свой node.
- Подсказка распознавателю (`--prompt`): имена участников и терминов проекта, чтобы `@codex` и идентификаторы
  распознавались.
- Текст вставляется в поле на проверку, не отправляется сам (настройка «отправлять сразу»).
- macOS спросит доступ к микрофону: в Info.plist нужен `NSMicrophoneUsageDescription`, пересборка Pult.app.
- Тот же конвейер в демоне потом расшифровывает голосовые из Telegram (Ф6).
- Облачные API расшифровки не берём: звук ушёл бы на чужой сервер.

## После 0.3.0 — редизайн и темы (решение владельца 20.10)

- **Редизайн окна** прорабатывается с Claude Design: раскладка, плотность ленты, подвал, Inbox, диалоги — одним заходом,
  а не правками по месту.
- **Тема и цвета** — выбор в «Настройки» → «Внешний вид» (экран заведён в M8f, раздел пока пустой: «темы и цвета — после
  редизайна»). Токены цветов — переменные CSS окна (`ui/src/styles.css`), тема переключает их набор.
- **До этого визуальных изменений нет**: новые функции встают в нынешний стиль, перекраски и перекладки — только в редизайне.
- Место в порядке — после 0.3.0, рядом с 0.4 «комнаты» (сроки — при планировании 0.4).
