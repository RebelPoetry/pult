## 1. Что подтвердил ресёрч v0.3 (три исследователя, на каждое несущее утверждение — проверяющий по первоисточнику)

## 2. Новая модель поставки и процессов (заменяет раздел 2 DELTA и Диаграмму A)
Проблема v0.2: демон жил ВНУТРИ приложения Electron. Отсюда три ловушки (AppImage, временная папка macOS, `ELECTRON_RUN_AS_NODE` с fuse) и боль обновлений на Mac.
Решение v0.3: демон выезжает из Electron совсем.
- Пакет `pult` — обычный Node-пакет (нужен системный Node ≥ 22; у друзей-разработчиков он есть или ставится `brew install node`). В пакете: демон `pultd`,
  CLI `pult`, заглушка `pult mcp-ask`, собранные файлы интерфейса. Ноль нативных модулей остаётся правилом.
  Ставится НЕ в глобальный префикс npm, а в собственную папку Пульта: `npm install --prefix ~/.pult/versions/<версия> <URL тарбола на своём VPS>`,
  затем симлинки `~/.pult/current → versions/<версия>` и `~/.local/bin/pult`. Так нет ошибки прав `EACCES` на системном Node в Linux, нет зависимости от
  того, какой Node сейчас выбран в nvm/fnm/volta, а оболочка всегда знает, где лежит пакет: `~/.pult/current`.
  Для пакета `pult` (демон, CLI) вопрос Gatekeeper исчезает: файлы, поставленные npm, не получают карантин. Для оболочки Electron ad-hoc подпись остаётся (раздел 5).
- Хозяин жизни демона — ОС, а не окно: `pult daemon install` пишет `~/Library/LaunchAgents/dev.pult.daemon.plist` (macOS) или
  `~/.config/systemd/user/pultd.service` (Linux). Служба запускает не `node` напрямую, а короткий скрипт `~/.pult/bin/pultd-launch`: он берёт сохранённый
  путь к `node`, а если тот умер (сменили версию в nvm, обновили brew) — находит `node` заново через логин-шелл и известные места и перезаписывает путь.
  `pult doctor` отдельно сообщает «служба указывает на несуществующий node». Ключи службы: macOS — `RunAtLoad`, `KeepAlive {SuccessfulExit: false}`,
  `StandardOutPath` и `StandardErrorPath` → `~/.pult/logs/pultd.log`; Linux — `Restart=on-failure`, `StandardOutput=append:%h/.pult/logs/pultd.log`,
  плюс `loginctl enable-linger` (иначе `systemd --user` гасит демон, когда закрыта последняя сессия пользователя; если прав не хватило — `pult daemon install`
  печатает точную команду). `pult daemon logs` читает этот файл; размер ограничен простой ротацией. Без установки службы демон поднимается по требованию:
  первая команда `pult` или оболочка запускают его отсоединённым. Закрытие окна демона не касается в принципе.
- Оболочка (окно) — тонкое приложение Electron: fuse `runAsNode` ВЫКЛЮЧЕН, бизнес-логики нет. Она находит установленный пакет `pult`, грузит файлы
  интерфейса из него через собственный протокол `app://` и общается с демоном через unix-сокет из main-процесса. HTTP-сервера у демона НЕТ:
  локальный HTTP-порт был бы доступен любой странице в браузере (подмена DNS, запросы с чужих сайтов), unix-сокет — нет.
- Следствие для обновлений: интерфейс и логика обновляются вместе с пакетом. `pult update`: по `latest.json` с VPS ставит новую версию в СВОЮ папку
  `~/.pult/versions/<новая>`, переключает симлинк `current`, мягко перезапускает демон (сессии уходят в `cold` и поднимаются через resume). Файлы под работающим
  демоном не перезаписываются. Если после обновления демон три раза подряд не поднялся — симлинк сам возвращается на прошлую версию. Подписи тарбола нет:
  подпись и тарбол лежали бы на одном сервере, это была бы видимость защиты; канал — HTTPS. Оболочка меняется редко.
- Оболочка и пакет расходятся по версиям. Страховка дешёвая: в preload оболочки одна константа версии моста; интерфейс из пакета сверяет её со своим
  поддерживаемым диапазоном и при расхождении показывает «обнови оболочку», а не ломается молча. Поэтому невозможность автообновления
  неподписанного приложения на Mac перестаёт болеть.
- Транспорт: unix-сокет `~/.pult/run/pultd.sock` (каталог 0700) + рукопожатие токеном из `~/.pult/run/token` (0600). Именованные каналы Windows убраны.
- Остальное из раздела 2 DELTA в силе: JSONL-журнал за одним модулем, lock-файл, `events.subscribe {since}` с курсора. Автозапуск — только так, как описано выше.
- Почему не другие варианты (короткая таблица на странице: Вариант · Что даёт · Почему нет):
  · Демон внутри Electron (`ELECTRON_RUN_AS_NODE`) · не нужен системный Node · три ловушки живучести, небезопасный fuse, обновления только вместе с оболочкой.
  · Самодостаточный бинарь демона (`bun build --compile` или Node SEA) · не нужен системный Node, нет дрейфа пути · плюс около недели работы и сборка под каждую
    платформу; оставлен как следующий шаг, если требование Node ≥ 22 начнёт мешать друзьям.
  · Node-пакет в собственной папке (ВЫБРАН) · первая фаза вообще без Electron, обновление одной командой, читаемый код у друзей · нужен системный Node ≥ 22.

## 3. Третий адаптер: opencode (новое; меняет Диаграмму A, таблицу компонентов, словарь событий, Диаграмму F)
- Интерфейс: `opencode serve` — HTTP + поток событий SSE. НЕ `opencode acp`: это протокол для плагинов редакторов (Zed, JetBrains, neovim), в его
  документации нет ни субагентов, ни разрешений. НЕ `opencode run --format json`: разовый прогон без ответов на запросы разрешений.
- Безопасность локального порта. У демона Пульта HTTP-порта нет именно потому, что локальный порт доступен страницам в браузере. `opencode serve` — такой же
  порт, и по умолчанию БЕЗ авторизации: в схеме `/doc` нет `securitySchemes`, у `serve` нет флага пароля. Но в бинаре 1.18.31 есть переменные
  `OPENCODE_SERVER_PASSWORD` и `OPENCODE_SERVER_USERNAME` (найдены в самом бинаре; в справке и схеме их нет). Решение: демон запускает `opencode serve` со
  случайным паролем на каждый старт, случайным портом (`--port 0`), только на `127.0.0.1`, без `--cors` и без `--mdns`; пароль живёт в памяти демона.
  Точная схема авторизации — пункт проверки Ф0. Не подтвердится — адаптер opencode откладывается, а не запускается открытым.
- Процесс: ОДИН `opencode serve --hostname 127.0.0.1 --port 0` на машину, под надзором демона. Папка — параметр КАЖДОГО запроса
  (`?directory=`), модель и агент — поля сессии (`POST /session`: `agent`, `model: {providerID, id}`, `parentID`). Сессия — единица изоляции, не процесс.
- Клиент: типы генерируются из живого `GET /doc` установленной версии (или `@opencode-ai/sdk`: `createOpencodeClient({baseUrl})`). Хэш `/doc`
  сверяется при старте, как схема протокола у Codex: расхождение → жёлтая плашка «протокол opencode изменился».
- Какие пути использовать (в схеме 1.18.31 по три варианта на действие — выбор закрывается в Ф0, а не во время Ф1.5):
  реплика — `POST /session/{id}/prompt_async` (ответ 204, результат приходит событиями); НЕ синхронный `POST /session/{id}/message` и НЕ
  `POST /api/session/{id}/prompt` (подтверждает только приём). Ответ на разрешение — `POST /api/session/{id}/permission/{requestID}/reply`; старый
  `POST /session/{id}/permissions/{id}` помечен deprecated. Остановка хода — `POST /session/{id}/abort` (есть и `POST /api/session/{id}/interrupt`).
  Поток — `GET /event?directory=…` на каждую открытую папку; не `/global/event` и не `/api/event`. Параметр `workspace` относится к экспериментальным
  `/experimental/workspace*` — на нём не строим, достаточно `directory`.
- События (`GET /event`, первым приходит `server.connected`). Имена дословно из схемы 1.18.31:
  текст — `message.part.delta`, `message.part.updated`; инструменты — часть `tool` с состояниями `pending | running | completed | error`
  (и пространство `session.next.tool.called / success / failed`); субагенты — часть `subtask` {agent, model, prompt, description} плюс
  `Session.parentID` и `GET /session/{id}/children`; разрешения — `permission.v2.asked` / `permission.v2.replied` (старый
  `POST /session/{id}/permissions/{id}` помечен deprecated — не использовать); вопросы — `question.v2.asked / replied / rejected`;
  статус — `session.status`: `idle | busy | retry`; ошибки — `session.error`.
  В 1.18 сосуществуют старые имена и пространство `session.next.*`: адаптер держит таблицу соответствия и контрактные тесты на записанном потоке.
- Схема ответа родная: в теле реплики `format: {type: "json_schema", schema, retryCount?}`, результат в `AssistantMessage.structured`, отдельная
  ошибка `StructuredOutputError`. Контракт стрелки теперь принудителен у ВСЕХ ТРЁХ провайдеров.
- Лимит бесплатных моделей: `session.status` с `type: "retry"` (внутри причина, провайдер, время следующей попытки) → статус Пульта `limited`.
- Состав бесплатных моделей меняется (в документации «limited-time»): список читается живьём (`GET /provider`, `opencode models`) при старте и по таймеру;
  идентификаторы моделей НИКОГДА не зашиваются в код и в шаблоны флоу — в ноде хранится провайдер и «класс» (дешёвый исполнитель), а модель выбирается из живого списка.
  «Класс» — логика Пульта, а не поле opencode: в `GET /provider` есть только `cost.input/output`, `family`, `name`, `limit`; дешёвый исполнитель = `cost == 0` плюс список разрешённых провайдеров.
- Бесплатным моделям Zen нужен сохранённый ключ провайдера `opencode` (у владельца он уже есть). На чистой машине друга `pult doctor` показывает красный пункт
  с точной командой входа. Появляется ли ключ сам при первом запуске — проверка Ф0.
- Чужие сессии: `GET /session` отдаёт все сессии без признака происхождения. Своими Пульт считает те, что записаны в его `sessions.json`; остальные показывает
  тем же списком «только чтение», что у Claude и Codex.
- У opencode нет различия «тёплая/холодная»: сессии лежат в его базе и всегда возобновляемы. Статус `cold` для него означает только «сервер не запущен».
- Хранилище самого opencode: `~/.local/share/opencode/opencode.db` — сессии переживают перезапуск сервера. Пульт НЕ читает `auth.json` из этой папки;
  наличие входа проверяется командой `opencode providers list` (алиас `auth`).
- opencode сам читает `AGENTS.md` и свои `.opencode/agents`, `.opencode/skills`; реестр Пульта получает их через `GET /agent` и `GET /skill`.
- Лицензия opencode — MIT (по сниппету поиска; файл LICENSE в репозитории прочитать до выпуска).
- Существующий relay-агент `opencode-assistant` внутри сессий Claude продолжает работать и не трогается.

## 4. Профиль сети: проверенные значения (заменяет абзац про прокси в разделе 6 DELTA). Таблица на странице: Кому · Что подставляем · Насколько проверено
- `claude` · `HTTPS_PROXY=http://127.0.0.1:10808`, `NO_PROXY=localhost,127.0.0.1,::1` · документация, дословно: SOCKS не поддерживается; порт проверен как HTTP-прокси.
- `codex` · `ALL_PROXY=socks5h://127.0.0.1:10808` · ежедневная практика владельца; официальной документации нет → в интерфейсе пометка «не документировано».
- `opencode` · `HTTPS_PROXY`, `HTTP_PROXY` = `http://127.0.0.1:10808`, `NO_PROXY=localhost,127.0.0.1` ОБЯЗАТЕЛЬНО · документация opencode предупреждает о петле:
  без `NO_PROXY` запросы к собственному локальному серверу уйдут в прокси.
- `git` · `git -c http.proxy=http://127.0.0.1:10808 …` на один вызов, глобальный конфиг не трогаем · документация git.
- `gh` · `HTTPS_PROXY` в окружении вызова · ключа прокси в `gh config` нет, поведение стандартное для Go.
- `npm` (обновление пакета `pult`) · `HTTPS_PROXY` в окружении вызова.
Правила: переменные задаются ПРИ ЗАПУСКЕ каждого дочернего процесса (`claude` читает их один раз при старте); демон не полагается на окружение шелла;
смена профиля сети требует перезапуска тёплых сессий — интерфейс говорит об этом прямо.
Проверка в Ф0 «мёртвый порт»: направить переменную на заведомо закрытый порт — CLI обязан упасть с ошибкой соединения. Прошёл напрямую — значит прокси игнорируется.

## 5. Поставка друзьям: macOS и Linux (заменяет раздел 7 DELTA)
- Установка одной командой: `curl -fsSL https://<VPS>/pult/install.sh | sh`. Скрипт: проверяет Node ≥ 22; ставит пакет `pult` из тарбола;
  на macOS кладёт оболочку в `/Applications` и на всякий случай снимает карантин (`xattr -dr com.apple.quarantine`); на Linux кладёт AppImage в
  `~/.local/bin` и `.desktop`-файл; в конце запускает `pult doctor`. `curl` не ставит карантин, поэтому диалога Gatekeeper у друга не будет.
  Скрипт короткий и читаемый: друг может прочитать его до запуска.
- macOS: оболочка с ad-hoc подписью (`mac.identity: null` + `codesign --sign -` в хуке `afterPack`) — без неё на Apple Silicon приложение не стартует.
  Если друг всё же скачал `.dmg` браузером: «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть».
  Ловушка с временной папкой (App Translocation) больше не опасна: демон живёт не в приложении.
- Linux: оболочка — AppImage (тихое автообновление без прав администратора); демон — в npm-пакете под `systemd --user`. Проблема размонтирования AppImage исчезла.
  `deb` и `rpm` не делаем (обновление требует пароля), Flatpak не делаем (песочница ломает модель).
- Обновления: пакет `pult` — командой `pult update` и баннером в интерфейсе; оболочка на Linux — сама; оболочка на macOS — редкий ручной шаг через тот же `install.sh`.
- Apple Developer Program: не платим (см. раздел 0). Homebrew cask не используем.
- Мастер первого запуска и `pult doctor`: Node ≥ 22 · найдены `claude`, `codex`, `opencode` и их версии · `claude auth status --json` → `loggedIn` ·
  `codex login status` → код 0 · `opencode providers list` (есть ли ключ провайдера `opencode` для бесплатных моделей) · путь к `node` в службе жив · на Linux включён linger · проба прокси · служба демона установлена или нет · выбор папки-воркспейса.
- Позиция по правилам, лицензия MIT, обмен флоу через git — без изменений против DELTA.
- Доступ к папкам на macOS: у владельца репозитории лежат в `~/Desktop/Development`. Демон под launchd, читающий `~/Desktop`, вызовет системный запрос доступа
  «Файлы и папки», привязанный к `node`. Это пункт проверки Ф0; запасной путь — поднимать демон по требованию из оболочки или терминала, которым доступ уже выдан.

## 6. План v0.3 (заменяет раздел 9 DELTA и Диаграмму D). Сроки — вечера и недели вечеров.
- Ф0 · Спайк · 6–8 вечеров · Без UI. 15 строк проверок: шесть типов базовых (каждая прогоняется на всех трёх провайдерах и считается одной строкой) плюс девять отдельных. Базовые (поток событий · ответ на запрос разрешения · resume ·

## 11. Врезка «Как проверялась v0.3» (рядом с врезками про v0.2)
Сначала ресёрч: три исследователя, и на каждое утверждение, от которого зависит решение, — проверяющий по первоисточнику. Проверка исправила три вещи: баг Codex #16242,
на который ссылался исследователь, давно закрыт; «перенос в Программы снимает временную папку macOS» оказался неверным — решает карантинный атрибут; оплата Apple из России
закрыта полностью, а не «затруднена».
Потом критика дельты: три критика (модель поставки, адаптер opencode, согласованность) и проверяющий на каждую серьёзную находку. 30 находок, 4 помечены блокерами,
5 опровергнуты проверяющими.
- Принято: собственная папка установки вместо глобального префикса npm; запуск службы через скрипт, который сам находит `node`; `enable-linger`; журнал службы в файл;
  версии в отдельных папках с автооткатом; константа версии моста; точные пути API opencode и остановка хода; ключ Zen в `pult doctor`; чужие сессии и статусы opencode;
  честная цена отказа от подписи.
- Найдено лидом на машине, мимо критика и проверяющего: у `opencode serve` ЕСТЬ защита паролем — переменные `OPENCODE_SERVER_PASSWORD` и `OPENCODE_SERVER_USERNAME`
  лежат в бинаре, хотя в справке и в схеме API их нет. Без этого адаптер пришлось бы откладывать. Второй раз подряд: спорный факт решает команда, а не голосование агентов.
