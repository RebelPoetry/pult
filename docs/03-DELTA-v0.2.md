# DELTA v0.2 — решение лида по ответам владельца (20.09.2026). Поверх SPEC.md + FACTS.md. При конфликте DELTA важнее.

## 0. Ответы владельца и что из них следует
1. «Личный проект, возможно пошарю друзьям, предел 15 человек» → без монетизации, без подписи кода на старте, у каждого свой локальный
   демон и свои подписки, никакого общего сервера. Фаза «Выпуск» из v0.1 превращается в «Сборку для друзей».
2. «Кросс-платформа» → macOS + Windows + Linux. Ноль нативных модулей в ядре, явная работа с путями, прокси, длинными путями и симлинками Windows.
3. «Доска живёт рядом со скриптами, умеет их открывать и редактировать, плюс мини-сессия» → на доске ДВА вида документов:
   родной флоу (граф, собирается стрелками из скиллов — исходная просьба) и вид скрипта (проекция существующего `.claude/workflows/*.js`).
   Мини-сессия — маленький чат агента, привязанный к одному файлу.
4. «Пульт заменяет herdr» → ядро выезжает из окна в фоновый демон `pultd`. Окно — один из клиентов. Появляется CLI `pult`
   с глаголами herdr, чтобы агенты оркестрировали из Bash.

## 1. Как принималось решение (короткая врезка на странице)
Три независимых архитектора дали три варианта: «сначала выпустить», «демон как стержень», «скрипт — источник истины».
Три судьи оценили их с трёх сторон: реализуемость на трёх ОС, объём для одного разработчика по вечерам, верность четырём ответам.
Оценки (реализуемость / объём / верность): сначала выпустить 8 / 8 / 6 · демон-стержень 7 / 6 / 8 · скрипт-нативный 5 / 3 / 7.
Решение лида: основа — «сначала выпустить». Из него НЕ принят один вырез: он убирал создание флоу стрелками, а это исходная просьба.
Взято у других: токен-рукопожатие на сокете, безопасный запуск `.cmd` на Windows, два движка исполнения, шесть видов нод,
карта маршрутов «эту ногу — на Codex».
Проверено на машине владельца после панели (Claude Code 2.1.278, codex-cli 0.155.0):
- у `claude` ЕСТЬ флаги `--effort`, `--setting-sources`, `--strict-mcp-config`, `--json-schema`, `--forward-subagent-text`, `--permission-prompts`, `--bg`;
  это снимает главный риск собственного движка («нельзя задать усилие ноге»).
- `claude auth status --json` отдаёт поле `loggedIn` (bool) и `authMethod`.
- `codex login status` печатает «Logged in using ChatGPT», код выхода 0.
- у `codex app-server` есть подкоманды `daemon`, `proxy`, `generate-ts`, `generate-json-schema`.

## 2. Новая модель процессов (меняет Диаграмму A)
- `pultd` — отсоединённый Node-демон. Запускается тем же бинарём Electron в режиме `ELECTRON_RUN_AS_NODE=1`, `detached: true`, `unref()`.
  Отдельный Node друзьям ставить не нужно. Владеет всем состоянием: сессии, адаптеры, журнал, git, разрешения, лимиты, расписание, Telegram.
  НЕ `utilityProcess`: тот умирает вместе с приложением.
- Окно Electron — тонкий клиент: рендер и сокет-клиент, без бизнес-логики. Закрыл окно — сессии работают дальше.
- `pult` — CLI-клиент того же сокета. Шим в `~/.local/bin/pult` и `%LOCALAPPDATA%\Pult\bin\pult.cmd`.
- Транспорт: JSON построчно через `net`. Unix-сокет `~/.pult/run/pultd.sock` (каталог 0700) на macOS и Linux, именованный канал
  `\\.\pipe\pult-<хэш домашней папки>` на Windows. Рукопожатие `hello {token}` из файла `~/.pult/run/token` (0600) на ВСЕХ ОС,
  потому что у именованного канала Windows нет прав доступа как у файла.
- Форма сообщений как у herdr: `{"id","method","params"}` → `{"id","result"}` или `{"id","error"}`, плюс `events.subscribe {since}`:
  клиент, который был офлайн, доигрывает события с курсора и ничего не теряет.
- Один экземпляр: lock-файл `~/.pult/run/pultd.lock` с pid и проверкой живости. Автозапуск при входе в систему — по желанию:
  launchd plist, `systemd --user`, `schtasks /sc onlogon`.
- Хранилище v0.2: БЕЗ SQLite. Дозапись JSONL: `~/.pult/events/<session>.jsonl`, `~/.pult/sessions.json`, `~/.pult/config.json`.
  Весь доступ — через один модуль хранилища. Когда поиск начнёт тормозить, модуль меняется на `node:sqlite` одним файлом.
  Причина: `better-sqlite3` требует пересборки под каждую версию Electron на трёх ОС, `node:sqlite` пока экспериментальный.
- Ноль нативных модулей в ядре: нет `node-pty`, нет `better-sqlite3`. Сборка на три ОС идёт без `@electron/rebuild`.

## 3. Замена herdr
- Принцип: herdr владеет терминалом и УГАДЫВАЕТ статус по тексту на экране — это его хрупкое место. Пульт читает структурные события.
- Тёплые сессии:
  · Claude — один долгоживущий процесс на сессию:
    `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --forward-subagent-text --session-id <uuid> --model M --effort E`.
    stdin открыт, следующая реплика не платит холодный старт. Срок жизни простоя не документирован: при EOF — тихий перезапуск с `--resume <uuid>`.
  · Codex — один общий app-server на машину, сессии — треды (`thread/start`, `thread/resume`, `turn/start`).
    У OpenAI это уже построено: `codex app-server daemon start|stop|restart`, `codex app-server proxy` (stdio → сокет демона),
    `codex agents` («Browse all agent sessions on the shared local app-server daemon»). ПРЕДПОЛОЖЕНИЕ ПО УМОЛЧАНИЮ: `pultd` не владеет
    процессом, а подключается к демону Codex через `codex app-server proxy`; треды переживают перезапуск `pultd`. Запасной путь —
    собственный дочерний `codex app-server` под надзором. НЕ ПРОВЕРЕНО и помечается так на схеме: можно ли задать `cwd`, модель и
    песочницу на каждый тред независимо; не мешают ли друг другу два одновременных хода; цел ли тред после перезапуска демона.
- После перезагрузки: сессии видны сразу со статусом `cold`, процессы не поднимаются штормом. Первая реплика поднимает сессию
  через `--resume` / `thread/resume`. Сессии с флажком «закрепить» прогреваются при старте демона — это закрывает разницу
  с herdr, который восстанавливает всё сразу.
- Статусы выводятся из событий, один перечень: `cold · idle · working · blocked_permission · blocked_question · limited · failed · done`.
  Claude: `system/init` → idle; `stream_event`/`assistant` → working; запрос в `mcp__pult__ask` → blocked_permission; `result` → idle или failed;
  текст лимита или `rate_limits.five_hour.used_percentage >= 100` → limited.
  Codex: `turn/started` → working; `item/commandExecution/requestApproval`, `item/fileChange/requestApproval` → blocked_permission;
  `turn/completed` читается по полю `turn.status`: `completed` → idle, `failed` → failed (сохраняем `turn.error`), `interrupted` → interrupted;
  `account/rateLimits/updated` переводит в limited ТОЛЬКО когда в снимке есть `rateLimitReachedType` (или `usedPercent >= 100`):
  само событие приходит при любом изменении расхода.
  К перечню статусов добавляется `interrupted`.
- CLI для оркестрации из Bash (глаголы как у herdr, скрипты переносятся заменой слова):
  `pult agent start <name> --kind claude|codex --cwd <dir> [--worktree <имя>] [--model M --effort E]`
  `pult agent tree <name>` — текстовое дерево субагентов из событий: видимость работы агентов появляется уже в Ф1, до окна
  `pult agent prompt <name> "текст" [--wait] [--until idle,blocked,done] [--timeout MS] [--json]`
  `pult agent read <name> [--since <event-id>] [--format text|json]`
  `pult agent wait <name>` · `pult agent list --json` · `pult agent stop|rm <name>`
  `pult perm list | approve <id> | deny <id> --reason "…"` · `pult run start <flow> --args '<json>'` · `pult events tail --since <id>` · `pult daemon status|logs|stop` · `pult doctor` (те же проверки, что мастер первого запуска)
  Коды выхода: 0 ок, 1 ошибка, 2 таймаут, 3 ждёт человека. В отличие от `herdr agent read`, ответ — структурные элементы с id, а не очищенный от ANSI экран.
- Изоляция с первого дня: `--worktree <имя>` создаёт рабочую папку на отдельной ветке одной командой `git worktree add` для обоих провайдеров.
  Правило «агент не работает в основной папке» действует с Ф1; полная матрица репозиториев, PR и CI приходят позже.
- Если при старте демона ни один CLI не найден или не залогинен: демон работает, провайдер помечен `unavailable` с причиной, `pult doctor` говорит, что сделать.
- PTY в ядре нет. Следствия сказаны прямо: первый вход (`claude` → `/login`, `codex login`) пользователь делает в своём терминале,
  Пульт только проверяет. Сырой терминал — позже и только как необязательная зависимость `@lydell/node-pty`: не собралась — ядро работает.
- Чужие сессии: `claude agents --json` показывает фоновые сессии Claude Code, запущенные из терминала или Claude Desktop
  (`state`, `waitingFor`, `cwd`); у Codex то же даёт `codex agents`. Пульт показывает те и другие списком только для чтения. Управлять ими как своими нельзя: `--bg` не совмещается с `-p`,
  потока событий нет.
- opencode: сейчас он доступен через relay-агента `opencode-assistant` внутри сессий Claude — это продолжает работать без изменений.
  Родной адаптер opencode — отдельное решение (см. открытые вопросы), потому что herdr запускал его напрямую.

## 4. Доска: два вида документов
### 4a. Родной флоу (исходная просьба, остаётся из v0.1)
Граф в JSON: ноды из реестра скиллов и агентов, стрелки, типизированные порты, провайдер/модель/усилие на ноде, гейты человека.
Исполняет собственный движок Пульта (движок «pult»): планировщик графа, нода = вызов `session.run` у демона, результат ноги по JSON-схеме
кэшируется в `node_runs` → прогон переживает лимит и перезапуск. Экспорт родного флоу в `.js` НЕ делаем.
Файл флоу лежит в репозитории воркспейса: `.pult/flows/<имя>.flow.json` — коммитится и расходится друзьям через git.
Каждая нода по умолчанию — свежая сессия (чистый контекст); опция ноды «продолжить сессию ноды X».
Контракт стрелки принудительный у ОБОИХ провайдеров: Claude — `--json-schema` → `structured_output`; Codex — `outputSchema` в `turn/start`
(в exec-режиме `--output-schema <FILE>`).
### 4b. Вид скрипта (новое)
Источник истины — сам `.js`. Граф — проекция, не сохраняется и не коммитится.
- Разбор: порт токенайзера из `scripts/check_model_tiers.py` на TypeScript (`_iter_code`, `_skip_string`, `_skip_regex`, `_match_paren`,
  `_opts_span`, `parse_object_literal`). Он уже верно понимает шаблонные строки с вложенными `${}` в ЭТИХ файлах. Без babel и recast.
- Шесть видов нод (по разбору пяти реальных скриптов):
  1. Фиксированная — статический `agent()` (пример: `probe:opencode`, `diff-review.js:113`).
  2. Веер по литеральному массиву — `parallel(DIMS.map(...))`, раскрывается в N детей с бейджем «4 из DIMS» (`diff-review.js:104–109, 134`).
  3. Динамический веер — массив пришёл из ответа прошлой ноги; ОДНА шаблонная нода с бейджем диапазона «×1–10», «×3–5»
     (`project-radar.js:109`, `web-research.js:116`). Фиксированное число детей не выдумывать.
  4. Табличная — вычисляемый `agentType` (`JUDGES_BY_PHASE`, `echo-gate-review.js:41–46 → 205–209`): рядом с нодой показана таблица,
     редактора agentType нет, в манифесте остаётся `{"agent":"*"}`.
  5. Код — детерминированная JS-логика после агентов, которая пересчитывает вердикт (`echo-gate-review.js:261–280`,
     `echo-release-check.js:291–299`). Серая, не редактируется, клик ведёт на строку. Визуально отличается от агентных нод,
     чтобы правка мышью не снесла жёсткий гейт вердикта.
  6. Страж — ранние выходы и regex-защиты аргументов (`safePath`, `safeTag`, `BASE`). Полоса-преамбула, только чтение.
- Что правится с доски: текст промпта, `model`, `effort`, `label`. Всё. Остальное — кнопка «открыть мини-сессию».
- Запись: точечная замена байтового диапазона по смещениям токенайзера (форматирование сохраняется само, файл не перепечатывается)
  → проверка синтаксиса оборачиванием в `AsyncFunction` (у скриптов `return` на верхнем уровне, `node --check` их отвергает)
  → запись во временный файл + `rename`.
- Транзакция гейта: копия `.js` и `.claude/model-tiers.json` в `~/.pult/undo/<ts>/` → правка обоих файлов → «гейт воркспейса»
  → код 0 оставляет, иначе оба файла возвращаются, stderr показывается дословно.
  Гейт воркспейса — любая команда из настроек воркспейса. У владельца это `python3 scripts/check_model_tiers.py`; у друзей гейта может не быть.
  Правила гейта в редакторе: переименование `label` правит `workflow_legs` в той же транзакции; у ноги на именованном агенте
  поля model/effort скрыты; у табличной ноги запись остаётся `{"agent":"*"}`.
- Новые ноги, новые фазы, перестройка вееров — работа мини-сессии: она пишет настоящий JS.
### 4c. Два движка исполнения
- Движок «claude-workflow» (делегирование, доступен рано): демон поднимает `claude -p … --allowedTools "Workflow(<name>)"` и шлёт реплику
  `Run /<name> with args <JSON>`. Документация: воркфлоу доступны в «non-interactive mode with claude -p», правило `Workflow(<name>)` разрешает один
  по имени. Плата: аргументы идут через слой промпта, хрупко; фазы воркфлоу в stream-json не документированы, поэтому доска рисует
  дерево субагентов по `parent_tool_use_id` и честно пишет «прогресс фаз недоступен». Resume — повторить ту же реплику в той же сессии через `--resume`.
- Движок «pult» (свой): сначала для родных флоу. Позже, как эксперимент, — для `.js`: скрипт грузится с подставленными
  `args / agent / parallel / phase / log`, `agent()` превращается в `session.run`. Карта маршрутов на прогон
  `{"review:*": "codex@low"}` запускает ТОТ ЖЕ неизменённый скрипт с ногой на Codex. Схема ноги уходит в Codex родным полем `outputSchema`
  (проверено по сгенерированной схеме протокола: «Optional JSON Schema used to constrain the final assistant message for this turn»).
  `.catch(fallback)`, который есть у каждого `agent()` во всех пяти скриптах, ловит только настоящие сбои хода.
  Карта маршрутов — параметр прогона; сохранённые наборы лежат в `~/.pult/routes/<скрипт>.json`. В сам `.js` она не пишется никогда.
  Эксперимент ограничен по времени: 4 вечера внутри фазы скриптов; не заработал — отбрасывается, фаза сдаётся без него.
  Эталон для сверки — тот же скрипт под движком «claude-workflow». `workflow()`, `budget()`, `isolation` не поддерживаются: в пяти скриптах они не используются.

## 5. Мини-сессия
Маленький чат агента на ОДНОМ файле: `SKILL.md`, агент `.md`, воркфлоу `.js`, `CLAUDE.md`, `AGENTS.md`.
- Запуск: `claude -p --input-format stream-json --output-format stream-json --verbose --setting-sources user --strict-mcp-config
  --mcp-config ~/.pult/mini-mcp.json --add-dir <папка файла> --allowedTools "Read(<файл>)" "Edit(<файл>)" --disallowedTools "Bash" "WebFetch" "WebSearch"
  --append-system-prompt-file <…> --permission-prompt-tool mcp__pult__ask --model sonnet --effort medium`
- `--setting-sources user` не грузит CLAUDE.md, агентов и MCP проекта: стартовый налог около 26 тыс. токенов исчезает.
- `--bare` запрещён: «In bare mode, Claude Code never reads OAuth credentials or the system keychain» → подписка перестаёт работать.
- Правило `Edit(path)` покрывает и Write, и NotebookEdit — одного правила достаточно.
- Флаг `--permission-prompt-tool` скрыт из `claude --help`, но существует: проверено, `claude --permission-prompt-tool` без значения отвечает
  «option '--permission-prompt-tool <tool>' argument missing», а выдуманный флаг даёт «unknown option».
- Дифф до применения: stdio MCP-сервер `mcp__pult__ask` — это НЕ один процесс в демоне. Каждый `claude` сам запускает свою заглушку
  (`pult mcp-ask`, тот же бинарь `pult`), а заглушка подключается к сокету `pultd` с тем же рукопожатием токеном. N процессов-заглушек, один общий Inbox. Каждый `Edit` приходит как `{file_path, old_string, new_string}` →
  двухпанельный дифф → Применить / Отклонить / Поправить и применить (`updatedInput`). Не на `/rewind`: он только интерактивный и постфактум.
- Скилл нельзя предзагрузить флагом. Первая реплика начинается с вызова нужного скилла: `/writing-for-agents` для документов агентам,
  `/skill-creator` для скиллов, `/workflow-authoring` для `.js`.
- После применения: гейт воркспейса, красная плашка при ошибке, откат одной кнопкой из `~/.pult/undo/<ts>/`.
- Провайдер v0.2 — только Claude. У Codex запросы `item/fileChange/requestApproval` ложатся в тот же интерфейс диффа, добавляется позже.
- Расход: модель и усилие выбираются на каждую мини-сессию, в шапке `total_cost_usd` из `result`, кнопка «Стоп».

## 6. Кросс-платформа
- Поиск CLI (результат кэшируется, запасной путь — «укажи бинарь»):
  macOS: PATH из логин-шелла, `~/.claude/local/claude`, `$(npm config get prefix)/bin`; codex — `~/.local/bin/codex`,
  `/Applications/ChatGPT.app/Contents/Resources/codex`. Linux: `~/.local/bin`, npm prefix.
  Windows: `%APPDATA%\npm\claude.cmd`, `%APPDATA%\npm\codex.cmd`, `%LOCALAPPDATA%\Programs\…`.
- Запуск на Windows: `.cmd`/`.ps1` — не исполняемые файлы. Запускать через `ComSpec /d /s /c` с аргументами массивом, НЕ `shell: true`:
  текст промпта не должен попадать в командную строку оболочки. Промпты вообще идут в stdin, не в argv.
- Окружение: GUI-приложение не видит `.zshrc`. Один раз при старте демона на macOS/Linux: `$SHELL -ilc 'env -0'`, таймаут 3 с, разбор по NUL,
  кэш `~/.pult/env.json`, подмешивается каждому дочернему процессу. На Windows не нужно: переменные из реестра наследуются.
- Профиль сети (новое, критично для России): у владельца `codex` обёрнут zsh-функцией с `ALL_PROXY=socks5h://127.0.0.1:10808` — GUI её не видит.
  В `~/.pult/config.json` прокси задаётся ОТДЕЛЬНО на каждого провайдера, потому что клиенты разные: `codex` — Rust, с `socks5h` у владельца
  работает; `claude` — нативный бинарь (Mach-O, не Node-скрипт), и ходит ли он через SOCKS, НЕ ПРОВЕРЕНО. Вероятно, ему нужен HTTP-прокси
  (`HTTPS_PROXY=http://127.0.0.1:<порт>`): у большинства локальных клиентов есть и SOCKS-, и HTTP-вход. Проверка в Ф0: запустить `claude -p`
  без шелл-обёртки, только с переменными, и убедиться, что трафик идёт через прокси (при лежащем прокси запрос обязан упасть).
  Для `git` и `gh` — свои значения.
  В строке состояния — проба TCP к прокси за 300 мс: красная точка «прокси лежит» до того, как потрачен ход.
- Git на Windows: `git -c core.longpaths=true worktree remove <path>` на один вызов, глобальный конфиг не трогаем. Проверка
  `LongPathsEnabled` в реестре: режим разработчика его НЕ включает. Симлинки скиллов (`.claude/skills/<имя> → ../../.agents/skills/<имя>`):
  проверка `core.symlinks`; если симлинк не раскрылся (`fs.realpath` → ENOENT/ELOOP) — реестр читает `.agents/skills` напрямую.
- Песочница Claude Code на нативном Windows не поддерживается (только WSL2): там единственная защита — брокер разрешений Пульта.
- Проверка контракта протоколов: при старте `codex app-server generate-json-schema` → хэш схемы сравнивается с проверенным; расхождение →
  жёлтая плашка «протокол Codex изменился». Для Claude — контрактные тесты на записанных потоках.
- CI: GitHub Actions `macos-latest` / `windows-latest` / `ubuntu-latest`: самотест демона на фальшивых CLI, которые проигрывают записанные
  потоки stream-json и JSON-RPC, плюс сборка `electron-builder --publish never`.

## 13. Новая Диаграмма F — «Жизнь сессии» (поставить в раздел про замену herdr)
Автомат состояний: `cold` → (первая реплика: `--resume` / `thread/resume`) → `idle` → (реплика) → `working` ⇄ `blocked_permission`
(approve / deny) ; `working` ⇄ `blocked_question`; `working` → `limited` (Claude: текст лимита или 100% окна; Codex: `rateLimitReachedType`) → (после `resets_at`) → `working`; `working` → `interrupted` → (реплика) → `working`; `working` → `idle`;
`idle` → (простой дольше `warm_ttl` — это настройка самого Пульта, значение выбирается после замера в Ф0) → `cold`; `idle` → `done` (закрыта); любой → `failed`.
Отдельной пометкой: «перезагрузка: все → `cold`; закреплённые → сразу `idle`». Цвета статусов те же, что на доске.

## 17. Врезка «Как проверялось решение» (короткий блок рядом с врезкой из раздела 1)
Дельту атаковали четыре критика: реализуемость, объём для одного человека, верность просьбам и Codex как вторая модель. На каждую серьёзную находку
работал проверяющий, который пытался её опровергнуть. Итог: 42 находки, 4 помечены блокерами (две из них — об одном и том же: порядок фаз).
- Принято: порядок фаз (родная доска переехала с пятого места на третье); родная схема ответа у Codex вместо обходного пути; готовый общий демон Codex;
  три ловушки живучести демона по одной на ОС; раздельные прокси на провайдера; статусы Codex по `turn.status` и `rateLimitReachedType`;
  заглушка MCP на каждую сессию; список противоречий со старым текстом.
- Отклонено лидом после проверки на машине: «флага `--permission-prompt-tool` не существует». Он скрыт из справки, но парсер его принимает.
  Ошиблись и критик, и проверяющий — поэтому спорные факты проверяются командой, а не голосованием.
