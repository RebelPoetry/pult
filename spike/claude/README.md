# Pult Ф0 — Claude leg

Готовая обвязка. Все проверки Claude из спайка написаны, синтаксис проверен, всё что можно было
проверить без входа — проверено. Вход сделан 21.09; прогон 1 после входа упёрся не в `claude`,
а в **сам харнесс** (прошитый прокси-профиль) — см. раздел «Сеть».

## Одна команда

```sh
# 1. в СВОЁМ терминале, один раз:
claude
/login          # закончить вход в браузере

# 2. потом:
cd ~/src/pult/spike/claude
./run-all.sh
```

Скрипт сам проверит вход (`claude auth status --json` → `loggedIn`) и, если входа нет, **остановится**
с понятным сообщением, ничего не потратив. Никакой скрипт здесь не логинится, не читает
`~/.claude/.credentials.json`, не трогает keychain и не использует API-ключ.

Опции:

| Флаг | Что делает |
|---|---|
| `--minutes 2,5,9` | интервалы простоя для S1 (по умолчанию) |
| `--only b1,s5` | прогнать только эти проверки (`b1 b2 b3 b4 b5 b6 s1 s3 s5 s7`); строки остальных в `results.json` не трогаются |
| `--skip-s1` | без warm-TTL: минус ~16 минут и минус 6 ходов |
| `--offline-only` | только то, что не требует входа |

Ночной прогон warm-TTL — отдельной командой, чтобы не гонять всё остальное по второму разу:

```sh
./run-all.sh --only s1 --minutes 20,40,60    # ~2 часа стены, 6 крошечных ходов
```

## Сеть

Профиль **выбирается, а не предполагается**. `lib.mjs` пробует TCP-коннект на `127.0.0.1:10808`
(300 мс): порт отвечает → `HTTPS_PROXY=http://127.0.0.1:10808` + `NO_PROXY=localhost,127.0.0.1,::1`;
порт закрыт → **прямое соединение вообще без прокси-переменных**. Переопределение —
`PULT_PROXY=auto|off|required` (`required` = «только через прокси», при закрытом порте прогон
останавливается с кодом 3 и ничего не тратит). Каждый скрипт пишет в свой лог запись
`{"kind":"network_profile","mode":"proxy|direct","port_open":…}`.

> **Если ты в регионе, который Anthropic не обслуживает — запускай с `PULT_PROXY=required`:**
>
> ```sh
> PULT_PROXY=required ./run-all.sh
> ```
>
> При `auto` (по умолчанию) упавший прокси **не останавливает прогон**, а молча роняет его
> в профиль `direct` — то есть выпускает трафик из твоей страны. `required` делает отказ
> **закрытым**: нет прокси → выход 3, ни одного хода. Именно из-за `auto` случился прогон 2.

Перед первым ходом `run-all.sh` проверяет, что `api.anthropic.com` отвечает **именно по выбранному
профилю** (`curl -m 8`, любой HTTP-код = достижим; при профиле proxy — через `-x`). Не отвечает —
внятный отказ и выход 4, квота не тронута.

### Страж выхода (egress guard)

Достижимости мало: важно, **из какой страны** уходит трафик. Перед любым ходом `egressCheck()`
дёргает `/cdn-cgi/trace` **по тому же профилю, что получит дочерний `claude`** (профиль proxy —
`curl -x http://127.0.0.1:10808`, то есть через HTTP-лицо смешанного порта; профиль direct —
обычный `curl`) и читает строку `loc=XX`. Порядок хостов: `api.anthropic.com` (тот самый хост,
с которым будет говорить `claude`), затем `cloudflare.com`, затем `www.cloudflare.com`; побеждает
первый, отдавший `loc`. В лог идёт `{"kind":"egress","mode":…,"loc":…,"ms":…}`.

Список-страж — `['RU','BY','CN','IR','KP','SY','CU']`. Это **консервативный список харнесса,
а не официальный список Anthropic**: ошибка в нём стоит остановленного прогона (выход 5),
но никогда — потраченного хода.

> **Открытый порт 10808 — не доказательство работающего VPN, и закрытый — не доказательство его
> отсутствия.** Замерено 21.09 подряд, в одном часу: (а) порт открыт, прокси отвечает `503` на
> обычный HTTP и роняет TLS-рукопожатие на любом хосте — приложение живо, туннель мёртв;
> (б) порт закрыт, а выход при этом `loc=XX` за 190 мс — VPN ушёл в режим TUN и завернул весь
> трафик мимо локального прокси. Про состояние сети честно отвечает только `egressCheck()`,
> поэтому решение «тратить ход или нет» принимает он, а не проба порта.

- `loc` из списка **или `loc` неизвестен** → скрипт выходит с кодом **5 ДО первого хода**,
  а его строка в `results.json` становится `verdict: "blocked"`,
  `details: «выход в сеть: <loc> — ходы не запускались»`.
- Перед каждым ходом **после простоя дольше 60 с** выход проверяется заново (это ровно случай
  `s1-warm-ttl.mjs`). Испортился за время простоя → второй ход **не отправляется**, в лог пишется
  `{"kind":"egress_lost"}`, интервал помечается `blocked`, а не `failed`.
- Аварийный обход: `PULT_EGRESS=skip` — проверка выключается, о чём громко орут в stderr.

### Отказ аккаунта/региона

Текст `api_error`, который ловится регуляркой `/disabled Claude subscription access/i`:

```
Your organization has disabled Claude subscription access for Claude Code · Use an Anthropic API key instead, or ask your admin to enable access
```

Он приходит как `{"subtype":"success","is_error":true,"terminal_reason":"api_error","api_error_status":403}` —
то есть `subtype` снова врёт. `resultSummary()` помечает такой ход `account_or_region_block: true`,
`networkFailure()` отдаёт `reason: 'account_or_region'`, любая проверка считает его **`blocked`,
никогда `fails`**, и весь `run-all.sh` немедленно встаёт с кодом **6** — потому что повторять
это в цикле значит биться в ту же стену.

Коды выхода: `1` не залогинен · `2` плохой аргумент · `3` нужен прокси, а его нет ·
`4` API недостижим · `5` выход в сеть заблокирован · `6` отказ аккаунта/региона.

Почему так: в прогоне 1 профиль был прошит в `lib.mjs` намертво, прокси лежал, а API был доступен
напрямую. Каждая проверка честно ждала по ~3 минуты и возвращала
`{"subtype":"success","is_error":true,"terminal_reason":"api_error"}` — и харнесс записывал это как
`fails`. Ходов не потрачено ни одного, времени — полтора часа. Журналы того прогона
в публичное дерево не входят (как и все `logs/` спайка).

Второй урок оттуда: `claude` **не падает быстро**. На мёртвом прокси он выдал 10 событий
`system/api_retry` за ~147 секунд, прежде чем сдаться (`max_retries: 10`). Поэтому ожидание хода
в `lib.mjs` само считает `api_retry` и после **трёх подряд** убивает процесс и возвращает
`{network_error: true, retries, last_error}` — проверка с таким исходом получает вердикт
`blocked`, никогда не `fails` и не `works`. Полезная нагрузка события:
`{type, subtype, attempt, max_retries, retry_delay_ms, error_status, error, session_id, uuid}`.

## Сколько это стоит

- Модель везде `haiku`, усилие `low`, промпты вида «reply with the single word OK».
- **~12 крошечных ходов** на всё, кроме S1: B1 (1), B2+S6 (2), B3 (2), B4 (1 + ход субагента),
  B5 (1), B6 (1), S3 (1 + ход агента воркфлоу), S5 (0 при ожидаемом падении), S7 (2).
- **+6 ходов** на S1 в режиме по умолчанию (2 хода × 3 интервала).
- Время: без S1 — примерно 3–5 минут. С `--minutes 2,5,9` — плюс 16 минут простоя.
  С `--minutes 20,40,60` — плюс 2 часа.

## Три находки, которые меняют дизайн

**1. Окружение надо вычищать по белому списку.** Процесс, запущенный из приложения Claude, несёт
25 переменных `ANTHROPIC_*` / `CLAUDE_*` (имена — в `logs/offline-probe-notloggedin.jsonl`, значений
там нет и не будет). Среди них `ANTHROPIC_BASE_URL`, который переадресовал бы API дочернего
`claude`, и `CLAUDE_CODE_MESSAGING_SOCKET` / `CLAUDE_CODE_MESSAGING_TOKEN`, которые привязали бы
дочерний процесс к чужой сессии. `pultd` обязан собирать окружение ребёнка из белого списка
(`HOME USER PATH LANG TERM TMPDIR` + сетевой профиль), а не вычитать «плохие» имена из своего.

**2. `result.subtype` — не признак успеха.** На провале аутентификации приходит
`{"subtype":"success","is_error":true,"terminal_reason":"api_error"}`. Адаптер обязан смотреть на
`is_error` и `terminal_reason`, иначе молча примет провал за удачный ход.

**3. Дешёвый старт и проектные воркфлоу несовместимы.** `--setting-sources user` (приём из S7,
экономит контекст проекта) **прячет** проектные скиллы и воркфлоу: `pult-echo.js` не появляется
в `slash_commands` при `user`, появляется при `user,project`. Значит это переключатель на уровне
ноды, а не глобальная настройка. Поэтому S3 намеренно ходит с `user,project`.

Мелочь, но в `pult doctor` попадёт: `claude auth status --json` **выходит с кодом 1**, когда
`loggedIn:false`, печатая при этом валидный JSON. Читать надо stdout, а ненулевой код не считать
поломкой команды.

## Чего эта обвязка не делает

- не логинится и не предлагает войти;
- не читает файлы с кредами и не печатает токены;
- не грузит службы launchd, ничего не ставит глобально, не трогает `~/.claude` и `rc`-файлы;
- пишет только сюда и в `../sandbox-a`.

S5 сначала делает **базовый ход по выбранному профилю** и только потом бьёт по мёртвому порту:
без успешной базы «упало» ничего не доказывает. Базовый ход не прошёл → `blocked`. Ожидание
мёртвого порта ограничено 45 секундами, в лог пишется время до первого `api_retry`.

S7 требует, чтобы **оба** хода вернули ненулевой расход токенов; иначе `blocked`. В прогоне 1
он сравнил два нуля и написал «works… saved 0».
